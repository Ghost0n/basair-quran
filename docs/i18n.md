# Interface languages (i18n)

The interface is written in Arabic and translated at runtime. **Quran text is
never translated or transliterated by this layer.** Translations of the
meanings are a separate, sourced feature: see `docs/quran-translations.md`.

## Supported locales

`apps/web/lib/i18n/locales.ts` is the list of supported locales:

- `ar`: the source language, marked reviewed.
- `en`, `fr`, `es`, `de`, `pt`, `it`, `nl`, `ru`, `tr`, `az`, `uz`, `bs`, `sq`,
  `id`, `ms`, `bn`, `hi`, `zh`, `ja`, `ko`, `sw`: left-to-right.
- `fa`, `ur`: right-to-left.

Every non-Arabic dictionary was **machine-drafted** and has not been reviewed
by a native speaker. The language picker marks these locales with `· β`.
Once a native speaker has reviewed a locale's JSON file, set `reviewed: true`
on that locale.

Surah names, Quran citations, root letters and ayah text stay in Arabic in
every locale.

## How it works

- **Message IDs are the Arabic source strings**, gettext-style. For example,
  `t("احفظ")` returns the active dictionary's entry, falls back to English,
  then falls back to the Arabic text. Placeholders are written `{0}`, `{name}`.
- **Counted phrases use `tn(id, count, vars)`**, as in
  `tn("{0} آية", n, { 0: formatNumber(n) })`. Never glue a number to a noun
  translated separately.
  - A locale's entry for a counted phrase is an object keyed by CLDR plural
    category, for example `{"one": "{0} verse", "other": "{0} verses"}`.
    Russian and Bosnian also need `few`/`many`; `other` alone is enough for
    Chinese, Indonesian, Malay, Japanese and Korean.
  - The category is chosen with `Intl.PluralRules`, using the rules of the
    dictionary the entry came from.
  - Arabic source forms live in `lib/i18n/plurals-ar.ts`, with all six
    categories: «آية واحدة، آيتان، ٣ آيات، ١١ آية، ١٠٠ آية».
  - A form may drop the number («آية واحدة») but must not add placeholders.
  - The codemod lists the ids used with `tn` in `lib/i18n/plurals.json`.
  - Both the check and the tests require each locale's categories (the
    Romance `many`, used only for millions, is optional).
- `lib/i18n/translate.ts` provides `t()`, `tn()`, `activeLocale()` and
  `setActiveDictionary()`. `t()` is a plain function, so it also works in
  module-level helpers. Module-level constants use getters (`get label() { return t("…") }`)
  so they are evaluated after the dictionary loads.
- `lib/i18n/provider.tsx` (`I18nProvider`, `useI18n`):
  - Loads `locales/<code>.json` by dynamic import, so each dictionary is its
    own chunk. The standalone app bundles only English and reads every other
    dictionary from a downloaded interface pack (`docs/offline-app.md`); it
    starts in English until the reader picks a language.
  - Sets `<html lang dir>`.
  - Remounts the tree under `<Fragment key={locale}>` when the locale changes.
- `lib/i18n/init-script.ts` runs before first paint:
  - Picks the locale from `localStorage["qb.locale"]`. Without an explicit
    choice the web opens in the browser's language: the first of
    `navigator.languages` the app speaks, by base language (`matchLocale` in
    `lib/i18n/locales.ts`, mirrored in the script). It falls back to Arabic and
    is not saved, so it never counts as a choice. The standalone app opens in
    English until onboarding.
  - Sets `lang` and `dir`.
  - Hides the body with `data-i18n-pending` until the dictionary has loaded,
    to avoid a flash of Arabic.
- For signed-in users the choice is also saved to the account
  (`ui_language`) and followed on other devices by
  `features/shell/locale-account-sync.tsx`. An account's language wins over
  the browser's.
- The digits (`numerals`) are a separate setting: changing the language keeps
  them. Only the first language choice adopts the language's usual digits —
  the standalone app's onboarding, and on the web the browser's language on a
  first visit or the first pick in Settings, while the digits are still the
  current language's (a reader who already set the digits keeps them):
  `lib/i18n/first-language.ts`.
- A language change remounts the app under the new dictionary; the screen
  stays where it is (the standalone app's launch — open on Home, boot — runs
  once per run, `features/app-mode/app-mode-root.tsx`).
- Direction:
  - The layout uses logical CSS (`start`/`end`, `inset-inline`).
  - Every rule that sets the Quran font, and the mushaf stage and page, force
    `direction: rtl`.
  - Directional icons (`components/icon.tsx`, `DIRECTIONAL`) get `dir-flip`
    and are mirrored in LTR, except inside the reader bar and the mushaf,
    where arrows follow page order.
- Scripts: `lib/script-fonts.ts` loads the matching Noto font on demand for
  Bengali, Devanagari, CJK and other scripts.
  - The fonts are self-hosted: `scripts/fetch-script-fonts.mjs` (run by
    `pnpm build`, by `build:app`, or alone as `pnpm fonts:scripts`) downloads
    each script's stylesheet and WOFF2 subsets into `public/fonts/noto/`
    (gitignored, about 17 MB, mostly CJK; a page only loads the subsets its
    text uses).
  - Without network at build time a script is skipped, and the browser loads
    it from Google Fonts instead (the `<link>` falls back on error).
- Dates and relative times use `Intl` with the active locale.
  - Some runtimes ship without relative-time data for a locale. Chromium, for
    example, prints «-3 h» for Bosnian, Azerbaijani and Uzbek, and English for
    Albanian.
  - In that case `relativeAge` falls back to the dictionary's plural phrases
    «قبل {0} دقيقة / ساعة / يوم».

## Layout that follows the text

Translations can be much longer than the Arabic («العرض» → "Anzeige",
"Mwonekano"), so controls size to their labels and adapt by measurement, not
by breakpoints. The global observer in `lib/auto-fit.ts` (started by
`I18nProvider`) works like this:

- It watches every `[data-autofit="N"]` element.
- It sets `data-fit` to the lowest level, from 0 to N, at which neither the
  element nor its `[data-fit-watch]` descendants overflow.
- It re-measures when an element resizes, its text changes, fonts load or the
  language changes.

Current uses:

- **Option groups** (`qb-fit-choice`): Settings choices, the display sheet, the
  navigate sheet tabs and the sign-in tabs. Each option sizes to its label.
  - Level 1 tightens the padding and drops the icons.
  - Level 2 lets labels wrap onto two balanced lines.
- **Tab strips** (`qb-fit-track`): Community tabs, the sort and type filters,
  the notebook tabs, the post view and the share sizes. Tabs never shrink
  below their label.
  - Level 1 tightens the padding.
  - Beyond that the strip scrolls, with edges that fade where more tabs hide,
    and the active tab stays in view.
- **Reader bar**: the surah name and page line are watched. When they don't
  fit, the bar sheds text in this order:
  1. the active tool's label;
  2. «العرض»;
  3. «انتقل»;
  4. "of 604".
- **Phone tab bar**: labels get a tighter face first, then two lines.

## The codemod: `apps/web/scripts/i18n.mjs`

```bash
node scripts/i18n.mjs report [--list] [--all]   # unwrapped Arabic literals
node scripts/i18n.mjs wrap [files]              # wrap literals in t(), add the import
node scripts/i18n.mjs catalog                   # regenerate lib/i18n/catalog.json
node scripts/i18n.mjs check                     # CI: unwrapped strings, catalog drift, placeholders
```

What the codemod skips:

- Quran text: detected by Uthmani-only marks or diacritic density.
- Single letters, keys and comparisons.
- Any line marked `// i18n-ignore`.
- The files in `EXCLUDED_FILES`: transliteration tables, surah and navigation
  data, numerals.

IDs used only through variables go in `lib/i18n/extra-messages.ts`.

CI runs `pnpm --filter web i18n:check`. `lib/i18n/locales.test.ts` checks
three things:

- every locale covers the whole catalogue;
- placeholders match between the source and each translation;
- no Quran text appears as a message ID.

## Adding or changing text

1. Write the Arabic string wrapped in `t()`. You can also write it bare and
   run `wrap`.
2. Run `node scripts/i18n.mjs catalog`.
3. Add the new IDs to every `locales/<code>.json` file. Counted phrases also
   need an entry in `plurals-ar.ts`. The Vitest suite lists
   any IDs that are missing.

## Adding a locale

1. Add a `LocaleInfo` entry to `locales.ts` (`code`, native name, `dir`,
   default `numerals`), without `reviewed`.
2. If the locale is right-to-left, add it to the RTL list in `init-script.ts`.
3. Create `locales/<code>.json` covering all of `catalog.json`.
4. If the script needs one, add a font to `lib/script-fonts.ts`.

Candidate locales not shipped yet:

- `ha`, `so`: not done yet; they need a native translator.
- `ps`, `ku`, `ta`, `kk`: drafts were dropped because their quality was too low.
